# GTO Wizard 前端設計與操作模式分析

> 來源:4 張截圖,情境為 **6Max / Cash / NL25 / 100bb / UTG preflop 開池**(With cold calls, 2.5x open)。
> 目的:拆解 GTO Wizard 的前端設計與互動邏輯,作為 `open-gto` UI 演進的參考。

---

## 1. 整體版面結構(五大區域)

```
┌─────────────────────────────────────────────────────────────┐
│ A. 頂部導覽列  Hold'em/PLO · Play/學習/練習/分析 · 升級/設定   │
├──────────────┬──────────────────────────────┬───────────────┤
│ B. 左側       │  C. 位置/動作序列條(UTG…BB)   │               │
│ 情境摘要      ├──────────────────────────────┤  E. 右側       │
│ Cash 100bb    │                              │  分析面板      │
│ 6Max NL25     │   D. 中央 13×13 手牌矩陣      │ (總覽/桌/權益) │
│ With cold..   │      (核心:策略視覺化)       │  + 行動頻率條  │
│ [改變]        │                              │  + 手牌明細    │
└──────────────┴──────────────────────────────┴───────────────┘
```

版面是典型的 **三欄式 + 上下條**:左欄管「載入什麼」、中欄管「策略長怎樣」、右欄管「深入分析」。資訊密度極高,所有東西都在同一畫面、不需換頁。

---

## 2. 各區域詳解

### A. 頂部導覽列
- **遊戲類型**:`Hold'em` / `PLO(新)` — 產品線切換。
- **模式分頁**:`Play`(對練)/`學習`(目前選中,看解)/`練習`(被考)/`分析`(上傳自己的手牌)。一個工具涵蓋「查 → 練 → 檢討」完整學習迴圈。
- **右側**:`升級`(綠色,付費鉤子)、`上傳`、全螢幕、說明、設定、帳號。

### B. 左側情境摘要欄
- 一句話顯示目前載入的解:`Cash 100bb` / `6Max NL25` / `With cold calls 2.5x`。
- 一顆 **`改變`** 按鈕 → 打開「解算結果庫」(見截圖 2)。
- 設計重點:**把「目前在看什麼」常駐顯示**,避免使用者迷失在深層樹裡。

### C. 位置/動作序列條(賽局樹導覽)— 關鍵設計
- 一排位置卡:`UTG 100 | HJ 100 | CO 100 | BTN 100 | SB 99.5 | BB 99`。
- 每張卡列出**該位置在此節點的可選動作**,且把「主線」動作粗體:
  - UTG:`Fold / **Raise 2.5** / Allin 100`
  - CO/BTN:`Fold / Call / Raise 8 / Allin 100`
  - SB:`Fold / Call / Raise 11 / Allin 100`
  - BB:`Fold / Call / Raise 13.5 / Allin 100`
- 這其實是 **把賽局樹「攤平成一條水平路徑」**:點位置 / 點動作就往樹的深處走。籌碼數(100、99.5)也顯示在位置上,反映已投入的盲注。
- 下方還有一排次級分頁:`策略 / 范围 / Breakdown / 报告:翻牌` + 矩陣顯示模式切換(`2/100` 是頁碼,代表可翻看 100 個翻牌面的報告)。

### D. 中央 13×13 手牌矩陣(核心)
- 標準起手牌網格:對角線=對子,右上=同花(s),左下=非同花(o)。
- **每格用「填色比例」表示混合策略頻率**:
  - 紅色 = 進攻(Raise / Allin),藍色 = Fold。
  - 純色格 = 純策略(100% 做某動作);**垂直分割的格 = 混合策略**(例:`K5s`、`Q9s`、`J9s`、`77`、`A5s`、`65s`、`54s` 都是部分紅部分藍)。
- 這是 GTO 視覺化的**業界標準語言**:一眼看出範圍形狀 + 哪些手是混合頻率。

### E. 右側分析面板(三個分頁切換上半部,下半部固定)
**上半部三個分頁:**
1. **`總覽`**(截圖 1):
   - 位置籌碼列、`1.5 BB` 底池、`底池赔率 40%`。
   - **`行動` 三條大頻率條**:`Allin 100 → 0% / 0 combos`、`Raise 2.5 → 17.5% / 231.88 combos`、`Fold → 82.5% / 1094.11 combos`,下方一條彩色比例尺。→ 把整個範圍的動作分佈量化成 %+組合數。
2. **`桌`**(截圖 3):
   - **俯視撲克桌圖**:六個位置繞橢圓桌排列,莊家鈕(D)、底池 `1.5bb 40%`、盲注 `0.5 / 1`。
   - 角落顯示節點屬性:`UTG ♣ OOP`(位置/不利位)、`EV ▲0.08`、`组合 ▲1326`。→ 提供「空間感」與該節點的 EV/組合數。
3. **`權益表格`**(截圖 4):
   - 需先選一個**翻牌後場景**才會出資料(`選擇翻牌後場景`),搭配一個 0–100 的圖軸。→ postflop equity 分析,跟 preflop 解耦。

**下半部固定:`手牌` / `總覽` / `筛选` / `阻挡牌`**
- 列出**具體花色組合**(如 `T♠6♠ / T♥6♥ / T♦6♦ / T♣6♣`、`4♠2♥…`),每個組合各自的 `Allin / Raise / Fold` 百分比。
- `筛选`(篩選)、`阻挡牌`(blocker 分析)→ 可依花色/阻擋牌深入鑽研。

## 3. 操作模式(互動流程)

```
①選解(解算結果庫)→ ②沿位置/動作條走賽局樹 → ③中央矩陣看範圍
                                              ↘ ④右側切換 總覽/桌/權益 看不同維度
                                              ↘ ⑤底部點單一手牌看花色組合明細
```

### ① 選解 — 「解算結果庫」(截圖 2)
不是即時運算,而是**從預先算好的解庫中用多維篩選挑一個**:
- `解算結果`:Cash / MTT / Spin&Go / HU SnG
- `籌碼`:隨機 / 300…20bb
- `類型`:經典 / Short / Ante / Straddle…(部分鎖,付費)
- `Preflop bet sizes`:No cold calls / **With cold calls** / 研究
- `玩家`:單挑 / **6Max** / 8Max / 9max
- `游戏级别`:cEV / NL10 / **NL25** / NL50…
- `开池尺度`:GTO / 2x / 2.25x / **2.5x** / 3x
- `Postflop bet sizes`:Single Size / Multi Size
- 下方結果表列出 `158 情況`,可加星收藏。

→ **「組態 → 載入解」** 模式,換取「秒開、零等待」。

### ②–⑤ 之後皆為唯讀瀏覽
載入後就是純導覽:走樹 → 看矩陣 → 切視角 → 鑽手牌。沒有「重新求解」按鈕(求解在後端離線完成)。

## 4. 視覺編碼邏輯(語意一致性)

| 編碼 | 意義 |
|------|------|
| 紅色 | 進攻動作(Raise / Allin) |
| 藍色 | Fold |
| 格內垂直分割比例 | 混合策略的各動作頻率 |
| 粗體動作(位置卡) | 該節點的主線/最高頻動作 |
| `%` + `combos` | 同時給「頻率」與「絕對組合數」兩種量度 |
| `EV ▲`、`▲1326` | 節點價值與到達該節點的組合數 |

一致原則:**同一個「動作→顏色」對應關係,貫穿矩陣、頻率條、手牌明細**,降低認知負擔。

## 5. 隱含的資料模型 / 狀態邏輯

```
Solution               ← 由 (format, stack, players, stakes, sizings) 組態決定
 └─ GameTree
     └─ Node           ← 由「位置 + 動作歷史」定位(目前所在節點)
         ├─ Strategy   : hand(169) → { action: frequency }      ← 中央矩陣
         ├─ Aggregate  : { action: (freq%, combos) }            ← 行動頻率條(由 Strategy 加權聚合)
         ├─ NodeMeta   : { player, IP/OOP, EV, combos, pot }    ← 桌視圖角落
         └─ ComboDetail: hand → [ (具體花色, {action: freq}) ]  ← 手牌明細
 └─ PostflopReports     ← 100 個翻牌面報告 + equity(與 preflop 解耦)
```

**核心心智模型**:「目前節點(Node)」是唯一的全域狀態,所有面板都是它的**不同投影**(矩陣=策略投影、頻率條=聚合投影、桌=空間投影、手牌=組合投影)。切換位置/動作 = 換 Node,所有面板同步更新。

## 6. 優點

1. **資訊密度高、單畫面完成**:選解、走樹、看策略、聚合統計、單手鑽研全在一頁,專業使用者效率極高。
2. **頻率即填色**:業界標準、直覺,範圍形狀與混合頻率一眼可讀。
3. **「節點」單一狀態 + 多投影**:心智模型清晰,各面板永遠一致同步。
4. **賽局樹攤平成位置條**:用一排卡片表達多層樹,比展開式樹狀圖省空間、好點。
5. **預算解庫 = 秒開**:把昂貴的求解搬到離線,前端只負責瀏覽,反應極快。
6. **量度雙軌**:同時給 `%` 與 `combos`,兼顧頻率直覺與絕對權重。
7. **學習閉環**:學習/練習/分析三模式覆蓋完整訓練流程。

## 7. 缺點

1. **學習曲線陡**:對新手資訊過載,小字、密集,需要懂術語(OOP、combos、blocker)。
2. **大量付費鎖**(🔒 滿佈篩選器):免費體驗破碎,常點到鎖住的選項。
3. **只能瀏覽預算解、不能即時自訂求解**(此介面內);postflop 還要另外選場景,流程斷裂。
4. **桌面導向、極不適合手機**:超寬三欄、密集格線,RWD 困難。
5. **頂列圖示過多**、語意不一(混了模式、產品線、帳號),首次使用者難辨識。
6. **顏色僅紅/藍二元**:多動作(3+ bet sizes)時靠垂直分段,顏色本身不編碼動作種類,需配文字才能分辨是哪個 size。

## 8. 對 `open-gto` 的啟發(差距與路線圖)

我們目前的 MVP 是 GTO Wizard 的「**單一節點、單一格式**」最小子集:

| 維度 | GTO Wizard | open-gto MVP 現況 | 演進方向 |
|------|-----------|------------------|----------|
| 求解 | 離線預算解庫 | **即時求解**(CFR+,push/fold) | 保留即時 + 加快取/解庫 |
| 賽局樹 | 多層樹、位置條導覽 | 單節點(SB jam / BB call) | 加入動作序列條、多街 |
| 矩陣 | 13×13 + 混合填色 | ✅ 已有 13×13 + 填色 | 加入混合策略多動作分段 |
| 右側面板 | 總覽/桌/權益 三投影 | 單一頻率(隱含於格) | 加「行動頻率條 + combos」聚合視圖 |
| 手牌明細 | 花色組合 + blocker | 無 | 之後可加(需 combo 級資料) |
| 格式 | Cash/MTT/Spin/HU + 多 stakes | 僅 HU push/fold | 漸進擴充 |

**最有性價比的下一步**(沿用 GTO Wizard 的成熟模式,但保留我們「即時求解」的差異化):
1. **行動頻率條**:在現有網格旁加一條「Jam X% / Fold Y% + combos」聚合條(對應「總覽」投影)——低成本、立刻提升專業感。
2. **籌碼是連續滑桿 + 即時重算**:這是我們勝過「預算解庫」的點,強化它。
3. **節點單一狀態 + 多投影** 的前端架構:即使現在只有一個節點,先用這個心智模型設計 state,日後加賽局樹不需重構。
4. 顏色語意:若未來支援多 bet size,讓**每個動作有固定顏色**(不要只靠紅/藍二元),避免 GTO Wizard「靠文字分辨 size」的缺點。
