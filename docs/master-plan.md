## 1. 願景與目標用戶

打造一個**新手也能用的德州撲克 GTO 助手**:使用者照真實牌局的順序設定情境,
直接看到「這手牌最該怎麼打」。長期目標是達到 GTO Wizard 的功能完整度,
但入口永遠對初學者友善。

- **主要用戶**:不太會打、想知道「現在該怎麼打」的初學者。
- **次要用戶**:想查範圍、練習、檢討的進階玩家。

## 2. 產品原則

1. **新手優先**:預設「設定 → 看建議」精靈;白話、中文、導覽(driver.js)。
2. **設定在前、GTO 在後**:照真實決策順序(盲注→籌碼→人數→位置→手牌→建議)。
3. **即時求解是差異化**:不像 GTO Wizard 只給預算解庫,我們現場算(短籌碼可行)。
4. **單一節點狀態 + 多投影**:同一個「目前節點」投影成矩陣 / 頻率 / 桌 / 權益。
5. **雙模式**:新手模式(精靈)與進階模式(完整 GTO Wizard 式佈局)共用同一引擎。

## 3. 核心 UX 流程(已與使用者確認)

```
① 盲注面額(僅換算 $↔bb,不影響 GTO)
② 有效籌碼 → 換算 bb(GTO 真正輸入)
③ 牌桌人數(HU 現有;6Max/9Max 規劃)
④ 位置 + 前面動作(誰先動 / 面對什麼)
⑤ 手牌
        ↓
   GTO 建議(白話) + 完整範圍表 + 頻率/combos
```

### 4.4 視覺語言(沿用截圖、補強缺點)
- 紅=進攻、藍=蓋牌、格內填色比例=混合頻率(已實作)。
- **多種加注尺寸時,每個動作給固定顏色**(避開 GTO Wizard「只靠文字分辨 size」的缺點)。
- 同一「動作→顏色」對應貫穿矩陣 / 頻率條 / 手牌明細。

## 5. 功能藍圖(分階段)

### Phase A — 單挑 push/fold 設定流程 ✅ 已完成
- 引擎:CFR+ 即時求解 HU 推/棄;169 equity 快取。
- 前端:設定精靈、查手牌建議、頻率條、範圍表、driver.js 導覽、中文。

### Phase B — 6Max/9Max 多位置 preflop + 賽局樹 🔧 下一步
- **引擎(重點工程)**:
  - 擴充賽局樹到多位置 preflop(RFI、面對 open 的 call/3bet/fold 等)。
  - 多人(6/9)→ 樹變大,需評估效能:可能導入**動作抽象**(限定幾個下注尺寸)
    與**快取/預算**部分節點(混合即時 + 快取)。
  - 先支援「開池(RFI)推薦範圍」這個最常用節點,再逐步加 3bet/4bet。
- **前端**:位置/動作序列條(C 區)、人數選擇解鎖、節點切換同步所有投影。
- 交付:選 6Max + 位置 + 手牌 → 看該位置的 GTO 開池/反應範圍。

### Phase C — 多種加注尺寸(不只 jam/fold)🔧
- 引擎:每節點支援多個離散下注尺寸(2x/2.5x/3x、3bet sizing…)。
- 前端:多動作頻率條 + 每動作固定顏色;矩陣格分段顯示多動作。

### Phase D — 翻牌後求解 + 桌/權益視圖 🔧
- 引擎:postflop 子博弈求解(需**牌面抽象/分桶**;工程量最大)。
- 前端:E 區「桌」與「權益表格」投影;翻牌面選擇器(對應截圖的「報告:翻牌」)。

### Phase E — 進階鑽研 + 練習/分析模式 🔧
- 手牌明細 / 篩選 / 阻擋牌(F 區)。
- 解庫收藏、情境分享。
- 「練習」(被考)與「分析」(上傳手牌)模式。

## 6. 技術架構

### 6.1 引擎(`engine/`,純 Python)
- 現有:`ExtensiveFormGame` 介面、CFR/CFR+/DCFR、exploitability、eval7、equity、push_fold(向量化)。
- 演進:
  - **B**:多位置 preflop game model;視樹大小決定是否需動作抽象。
  - **C**:節點支援多下注尺寸。
  - **D**:postflop game model + 牌面抽象(k-means / 分桶);效能關鍵。
- 效能策略:小樹即時解;大樹混合「即時 + 預算快取(.npy/sqlite)」。

### 6.2 後端 API(`api/`,FastAPI)
- 現有:`POST /solve`(push_fold)。
- 演進:`/solve` 參數擴充(game/format、players、position、action node、bet sizes);
  加 `/scenarios`(可用節點列舉)、快取層。

### 6.3 前端(`web/`,React+TS)
- 狀態模型:**單一 `Node`(情境 + 動作歷史)為全域狀態**,投影成矩陣/頻率/桌/權益。
  現在只有一個節點,但結構先就位,Phase B 加賽局樹不需重構。
- 模式切換:新手(精靈)/ 進階(密集佈局)共用同一 Node 狀態與資料。
- 元件:`SetupFlow`、`HandPicker`、`Verdict`、`FreqBar`、`RangeGrid`(已);
  待加 `PositionTree`(C 區)、`TableView`/`EquityTable`(E 區)、`ComboDetail`(F 區)。

## 7. 里程碑與順序

1. **Phase B**(下一個):6Max 多位置 preflop(先 RFI)+ 位置/動作條 + 進階佈局骨架。
2. **Phase C**:多下注尺寸 + 多動作顏色。
3. **Phase D**:postflop + 桌/權益。
4. **Phase E**:手牌明細、練習/分析、解庫。

每個 Phase 開工前,用 `writing-plans` 產出該階段的 TDD 任務清單;每階段都能獨立交付、可測試。

## 8. 風險與取捨

- **6Max 完整 preflop 樹很大**:全節點即時求解可能太慢 → 先做最常用節點(RFI),
  其餘用動作抽象 + 快取;誠實標示哪些情境已支援。
- **Postflop 需要牌面抽象**:精度 vs 速度的權衡(EHS / 分桶);這是 Phase D 的核心難點。
- **即時 vs 預算**:深籌碼/多人即時解不可行時,退回「預算快取」模式(像 GTO Wizard),
  仍保留短籌碼即時解的差異化。
- **複雜度 vs 新手友善**:進階功能一律藏在「進階模式」,新手模式維持極簡。
